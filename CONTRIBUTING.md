# Contribuindo

1. Crie uma branch a partir da `main` (`feature/...`, `fix/...` ou `docs/...`).
2. Preserve a separação entre interface, API, worker e domínio.
3. Inclua testes para toda mudança de comportamento.
4. Execute os testes locais e o build Docker antes de abrir um pull request.
5. Registre decisões arquiteturais duradouras em um ADR.

Não coloque segredos, dados de clientes, alvos reais ou evidências no repositório. Ferramentas ofensivas futuras deverão exigir escopo autorizado explícito e trilha de auditoria.
